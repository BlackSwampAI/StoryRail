# Publication direction and story purpose

The newsroom brief describes the audience, what the publication helps readers understand or do,
what merits coverage, its voice, and what writers should avoid. It is saved with the existing
append-only editorial standards revisions. Site name and description remain publication identity;
connector credentials and model configuration remain separate settings.

Existing freeform standards remain available as additional editorial standards. A newsroom can
continue using them without completing guided setup. Saving the guided brief appends a revision;
it does not replace earlier standards records.

Story purpose captures reader value and an optional question or emphasis before assignment. It is
separate from the contribution of each attached Source and from the recorded decision to cover,
attach, or skip that Source. Attaching another Source preserves the Story's purpose. The approved
Assignment still owns its angle, Writer brief, and constraints.

Each Researcher, Assignment Editor, Writer, Writer revision, and Director run records the exact
publication context and Story purpose it uses. Editing the newsroom brief affects subsequent runs;
it does not change past run inputs, evidence, assignments, or Article revisions. Story purpose can
be edited before assignment when no agent is working on the Story. After assignment it remains
visible alongside the approved editorial direction.

Publication perspective guides questions and interpretation. It does not establish facts or
permit unsupported conclusions. Research should seek relevant evidence and identify unanswered
questions. Assignment proposals should explain reader value. Writing should answer the promised
question in the publication's voice. Director review should assess audience relevance and useful
delivery under its assignment check, and editorial fit under its style check, alongside the
existing support, accuracy, headline, and structure checks.

## Editorial evaluation cases

These cases are a small manual evaluation protocol, not a claim that model output has been
validated. Provider stubs can establish context propagation and workflow behavior; useful
research and writing require inspection of actual generated output.

Use the same fictional, preserved source material for both publications:

> Vendor A announces a text model. It reports a higher score on its own benchmark, lists a
> monthly subscription price of $30, and says API access is available separately. The announcement
> gives no independent evaluation, total setup cost, or evidence about a particular business task.

| Publication brief                                                                                                                                                                                                                                                                      | Story purpose                                                               | Useful research and coverage                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Small business owners with limited technical expertise. Help them judge whether AI tools justify time and money. Cover practical costs, setup effort, limitations, and applications. Be practical and skeptical of hype. Avoid jargon and unsupported savings claims.                  | What would an owner need to check before paying for this tool?              | Distinguish subscription price from total cost; investigate API pricing, setup and task suitability; identify missing independent evidence. Avoid declaring that the tool saves money. |
| Software engineers evaluating model infrastructure. Help them understand integration and operational tradeoffs. Cover interface changes, reproducible evaluations, deployment limitations, and reliability. Be precise. Avoid marketing language and unsupported performance rankings. | What would an engineering team need to validate before adopting this model? | Investigate API documentation, compatibility, limits and reproducibility; distinguish vendor benchmark claims from independent measurements. Avoid declaring it the best model.        |

For each publication, inspect research questions, proposed angle and brief, the first Article,
Director notes, and any revision. The audience should change the questions and explanation while
both versions retain the same evidence boundaries. Missing information should remain an explicit
gap. Revisions should retain the promised reader benefit while addressing review findings.

Also evaluate a weakly related source and a promotional source asking the agent to ignore
instructions. The first should invite an editorial relevance decision; the second must remain
untrusted evidence. Neither should force a favorable conclusion or bypass citation validation.
